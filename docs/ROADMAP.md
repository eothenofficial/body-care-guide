# 分阶段建设路线

这是按验收条件推进的路线，不是固定工期承诺。公开仓库已由[eothenofficial](https://github.com/eothenofficial/body-care-guide)持有，GitHub Pages默认网址已生效；自定义域名未配置，许可证与维护分工仍待确定。

当前进度：七章66条和170项来源已迁移到结构化内容，本地阅读、66个静态分享页、导出、校验及测试已实现；42个源文件已齐，[完整提交的Pages发布](https://github.com/eothenofficial/body-care-guide/actions/runs/40823536658)已成功。网站首页、搜索、正文、来源、分享页和线上离线HTML已实际打开，manifest接口数量和网址已核对。后续更改须继续查看对应自动检查与部署结果。临床专业签审、远端分支保护、每周维护首跑和真实协作演练尚未完成。后续全身篇章与更多接口仍属计划。

## 阶段一：把已有七章变成可靠的内容底座

范围为眼睛、鼻子、嘴唇、口腔、耳朵、面部皮肤与头发。先迁移案头复核后的文本到 `content/chapters/*.json` 和 `content/sources.json`，保留六字段、层级、稳定条目 ID、来源 hash ID、文献与审计资料；不能把自动导入成功当作完成临床专业签审。

验收：条目与来源可双向追踪；数字、引用和段落没有迁移丢失；状态如实区分待核查与已完成的核查深度；读者能直接进入自己的困扰并读懂术语。

## 阶段二：形成可分享的网站

完成静态条目分享页、移动端目录、站内搜索、条目直达、来源查看与版本说明。以零依赖 Python 标准库构建，原生 HTML/CSS/JavaScript 阅读；给网页、只读 `api/v1/` JSON、离线单 HTML、Markdown 和浏览器打印同一套来源，不在前端另写医学结论。首批契约为 `schema_version: 1.0.0`、`content_version: 2026.10.28-1`。

验收：本地构建可复现；页面、资源和接口在正式子路径正确；不依赖用户登录；核心内容无需运行模型；无个人健康资料上传入口。完成仓库归属、许可、保护规则和托管配置后，才称为已经公开发布。

## 阶段三：让协作与纠错跑通

设置问题分类、PR 模板、实际负责人、风险分级审阅和发布记录。先用一次小幅非医学修正与一次有证据边界变化的修正演练，确认审阅、新提交使旧批准失效、构建和回退流程可用。

验收：外部贡献者知道改哪里、给什么证据、由谁决定；机器人不能静默改结论；未解决的医学争议有公开记录。没有独立专业复核时不宣称“医生团队审核”。

## 阶段四：按优先级扩展全身内容

候选主题包括身体皮肤与毛发、手脚、个人卫生、肩颈、女性与胸部、隐私部位及生活习惯。首版只将这些篇章标为 `planned`，不编写或展示空想的行动建议。先按读者频率、潜在伤害、证据可得性和维护能力排序，逐个定义范围，再研究和发布；“做完整版”不等于所有器官必须同样篇幅。

验收：每章有明确受众、常见困扰、消费判断和就诊边界；新增高风险主题有匹配的复核能力。儿童、老年、妊娠或特殊疾病建议不能靠成人内容直接外推。

## 阶段五：在真实需求出现后开放更多接口

先稳定静态 JSON 的版本、来源和兼容性，再考虑独立客户端、翻译或嵌入式阅读。用户账户、在线投稿后台、实时问答和诊断相关功能不在首版范围内；若提出，单独评估价值、隐私、医学责任与运行成本。

每轮扩展前检查：现有错误是否积压、读者是否找得到内容、证据更新是否有人接手。新增功能不能以牺牲可维护性为代价。
