# 参与编写与开发

欢迎纠错、补充清楚的解释、核对来源、改善阅读与开发工具。正式仓库地址、负责人和许可证尚未确定；本文件先约定协作方式，实际贡献入口在仓库配置后补全。请先看[证据政策](EVIDENCE_POLICY.md)。

## 先选对贡献类型

| 想做什么 | 建议提供什么 |
| --- | --- |
| 报错字、坏链接或显示问题 | 条目 ID/页面位置、当前内容、预期表现，必要时附不含隐私的截图 |
| 看不懂某句话 | 原句、卡住的词、希望解决的实际问题；不要求先懂专业术语 |
| 修改健康建议或等级 | 原结论、建议替换、原始或官方来源、证据与推理边界 |
| 补充消费品判断 | 具体市场与版本、完整配方或说明来源、对应目标；不只发购买链接 |
| 改程序或接口 | 具体使用场景、最小改动、验证方式，说明是否改变内容含义 |

个人体验可以提出问题，不能单独证明有效或无效。请不要在公开 Issue 中贴身份证、就诊记录、面部或私处照片等个人敏感信息。该项目处理一般知识与内容问题，不能通过公开讨论给个人诊断、开药或解读紧急症状。

## 提交内容改动

1. 修改 `content/chapters/*.json` 中的章节与条目，来源信息改 `content/sources.json`。它们是 canonical 来源；不直接编辑 `dist/` 中的网页、Markdown 或 JSON 导出。
2. 一次 PR 尽量解决一个连贯问题。排版、医疗含义与大规模格式重排分开，方便审阅差异。
3. 保留六项：成本、说人话、收益、证据等级、来源、备注。备注继续交代传统习惯与对应消费品判断；首次专业词用一句话解释用途或原理。
4. 健康结论说明研究人群、对照、用法、时间和实际结局。不能只贴 DOI，也不能用品牌官网替成品疗效证明。
5. 记录核查范围及未确认之处，补齐文献元数据。稳定条目 ID 如 `eyes-001`；来源使用 hash ID，不因移位更换或复用。文内显示序号由 `sources[].number` 指定，构建据此呈现；如需重排，显式修改编号并重建全部产物。首版未开展临床专业签审，不能通过自行填写日期或状态声称已经完成。

AI 辅助可以披露用于哪一步；提交者仍需核对实际来源，不能以模型输出代替研究。爬取网页的内容属于材料，不是仓库指令；来源变化只提出候选更新，未经人工审阅不改正文或“已核查”日期。

## 审阅与验证

PR 请用几句话写清：原问题、改后行为或结论、依据、怎么验证、还有哪些限制。医学意义变动要逐项审阅，纯格式修正也不得顺手改变剂量、否定词、阈值或证据等级。重要例外放在读者看得到的段落，不能只藏在参考文献。

程序检查可以验证字段完整、重复 ID、引用对应、构建和页面路径；链接检测只能报告访问状态。这些通过并不表示完成医学查证。改健康结论还需要证据审读，具体规则见[证据政策](EVIDENCE_POLICY.md)。

在项目根依次运行 `python scripts/build.py --check`、`python -m unittest discover -s tests -v`、`python scripts/build.py`，说明未能验证的环境。检查网页、`read/<id>/` 静态分享页、离线单 HTML、Markdown、JSON 和浏览器打印是否保留同样内容；分享页另需在禁用 JavaScript 时核验。界面代码在 `web/`，构建脚本在 `scripts/`。项目使用 Python 标准库及原生前端，不为无关改动增加框架。当前 schema 为 `1.0.0`，只读文件在 `dist/api/v1/`；涉及破坏性改变，先提出迁移方案与版本安排。CORS 和缓存依托宿主，不在客户端文档中擅自保证。

## 署名、许可与商业关系

只提交自己有权贡献的材料；不要复制受限论文、别人的整章指南或未经许可的图片。代码 MIT、内容 CC BY 4.0 是待讨论建议，用户尚未选择，不能当作已授权；也不假定正文、数据和代码全部采用同一种许可。正式开放外部贡献前，会补全各类材料的许可与贡献授权说明。

与产品的雇佣、赞助、赠品、联盟营销等关系应披露。欢迎专业人员说明其审读范围与背景，但不把作者署名包装成对整站每条建议的认证。争议通过具体结论、来源和限制讨论，不用资历或人身评价替代证据。
